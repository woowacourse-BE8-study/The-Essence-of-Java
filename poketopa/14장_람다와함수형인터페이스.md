# 14장. 람다와 함수형 인터페이스 (Lambda & Functional Interface)

> 자바는 **함수도 일급 객체처럼** 다룰 수 있게 되었습니다. 그 핵심 통로가 **함수형 인터페이스 + 람다** 입니다.
> "함수를 인자로 넘기는" Python 의 자연스러움을 자바답게 구현한 방식을 정리합니다.

---

## 1. 출발점: "함수를 인자로 넘기고 싶다"

### 1.1. Python — 함수가 일급 객체

```python
def say_hello():
    return "안녕하세요!"

def say_goodbye():
    return "안녕히 가세요!"

def execute_function(func):
    print("작업을 시작합니다...")
    print(func())
    print("작업이 끝났습니다.")

execute_function(say_hello)
execute_function(say_goodbye)
```

### 1.2. Java — 함수형 인터페이스로 우회

자바는 모든 것이 객체이므로 *함수* 를 직접 넘길 수 없습니다. 그래서 **"메서드 하나짜리 인터페이스"** 를 정의하고, 그 인터페이스의 *구현체* 를 넘기는 식으로 우회합니다.

```java
// 1️⃣ 메서드 하나짜리 인터페이스 = 함수형 인터페이스
@FunctionalInterface
public interface Greeting {
    String greet();
}

// 2️⃣ 익명 클래스 / 람다로 구현체 생성
Greeting hello   = () -> "안녕하세요!";
Greeting goodbye = () -> "안녕히 가세요!";

// 3️⃣ 메서드의 파라미터로 받음
public void execute(Greeting g) {
    System.out.println("작업을 시작합니다...");
    System.out.println(g.greet());
    System.out.println("작업이 끝났습니다.");
}
```

## 2. 함수형 인터페이스의 규칙

```java
@FunctionalInterface
public interface MyFunc<T, R> {
    R apply(T t);            // ✅ 추상 메서드는 정확히 1개

    default R applyTwice(T t) {  // ✅ default 메서드는 여러 개 OK
        return apply(t);
    }

    static MyFunc<String, Integer> length() { // ✅ static 메서드도 OK
        return String::length;
    }
}
```

- **추상 메서드는 정확히 1개** (SAM: Single Abstract Method).
- `default`, `static`, `Object` 메서드(`toString`, `equals` 등 재선언) 는 개수에 포함 안 됨.
- `@FunctionalInterface` 는 *컴파일러가 위 규칙을 검사* 하게 하는 안전장치 (선택이지만 강력 권장).

## 3. 람다 표현식 → 익명 클래스가 아니다

자바 8 이전에는 동일한 일을 **익명 클래스** 로 했습니다.

```java
// 익명 클래스
Comparator<String> byLength = new Comparator<String>() {
    @Override
    public int compare(String a, String b) {
        return a.length() - b.length();
    }
};

// 람다
Comparator<String> byLength2 = (a, b) -> a.length() - b.length();

// 메서드 참조
Comparator<String> byLength3 = Comparator.comparingInt(String::length);
```

### 람다와 익명 클래스의 차이 (면접 단골)

| 구분 | 익명 클래스 | 람다 |
| --- | --- | --- |
| **`this`** | 익명 클래스 인스턴스 | **외부 클래스 인스턴스** |
| **컴파일 결과** | `.class` 파일 생성 (`Outer$1.class`) | `invokedynamic` + `LambdaMetafactory` |
| **외부 변수** | effectively final 만 캡처 | 동일 |
| **외부 인스턴스 참조** | 항상 보유 (`this$0`) | **캡처가 없으면 갖지 않음** ✅ |

> **결론**: 람다는 익명 클래스의 syntactic sugar 가 아닙니다. 외부 인스턴스를 안 잡기 때문에 **메모리 측면에서도 우수** 합니다 (7장 내부 클래스 참고).

## 4. JDK 표준 함수형 인터페이스 (`java.util.function`)

자주 쓰는 형태는 JDK 가 이미 만들어두었습니다. **직접 만들기 전에 표준에 없는지 먼저 확인** 하세요.

| 인터페이스 | 시그니처 | 용도 |
| --- | --- | --- |
| **`Function<T, R>`** | `R apply(T t)` | 변환 (T → R) |
| **`Predicate<T>`** | `boolean test(T t)` | 조건 판별 |
| **`Consumer<T>`** | `void accept(T t)` | 소비 (입력만) |
| **`Supplier<T>`** | `T get()` | 공급 (출력만) |
| **`UnaryOperator<T>`** | `T apply(T t)` | T → T |
| **`BinaryOperator<T>`** | `T apply(T a, T b)` | 두 T → T |
| **`BiFunction<T, U, R>`** | `R apply(T t, U u)` | (T, U) → R |
| **`Runnable`** | `void run()` | 입력/출력 모두 없음 |
| **`Callable<V>`** | `V call() throws Exception` | Supplier + checked exception |

### 활용 예시

```java
Function<String, Integer> length    = String::length;
Predicate<String>         isBlank   = String::isBlank;
Consumer<String>          printer   = System.out::println;
Supplier<LocalDateTime>   nowSup    = LocalDateTime::now;
BiFunction<Integer, Integer, Integer> sum = Integer::sum;
```

## 5. 실전 패턴 ①: Template Method 를 람다로 (Callback)

자바의 함수형 인터페이스가 *진가* 를 발휘하는 곳이 바로 **Template + Callback** 패턴입니다.

### 5.1. 콜백용 함수형 인터페이스 정의

```java
@FunctionalInterface
public interface ConnectionCallback<T> {
    T doInConnection(Connection connection) throws SQLException;
}
```

### 5.2. 트랜잭션 템플릿 구현

```java
@RequiredArgsConstructor
public class TransactionTemplate {

    private final ConnectionFactory connectionFactory;

    public <T> T executeInTransaction(final ConnectionCallback<T> callback) {
        try (Connection conn = connectionFactory.getConnection()) {
            final boolean previousAutoCommit = conn.getAutoCommit();
            conn.setAutoCommit(false);
            try {
                T result = callback.doInConnection(conn);
                conn.commit();
                return result;
            } catch (SQLException e) {
                rollback(conn, e);
                throw new IllegalStateException("트랜잭션 실패", e);
            } catch (RuntimeException e) {
                rollback(conn, e);
                throw e;
            } finally {
                conn.setAutoCommit(previousAutoCommit);
            }
        } catch (SQLException e) {
            throw new IllegalStateException("커넥션 획득 실패", e);
        }
    }

    private static void rollback(final Connection conn, final Throwable exception) {
        try {
            conn.rollback();
        } catch (SQLException e) {
            exception.addSuppressed(e);
        }
    }
}
```

### 5.3. 사용하는 쪽 — 비즈니스 로직만 람다로 주입

```java
public long saveNewGame(final Game game) {
    return transactionTemplate.executeInTransaction(conn ->
        gameDao.insertInitialGameAndPieces(conn, InitialGamePersistDto.from(game))
    );
}
```

### 5.4. 왜 이 패턴이 좋은가?

| 관점 | 장점 |
| --- | --- |
| **OCP (개방-폐쇄 원칙)** | 트랜잭션 처리 로직(commit/rollback)은 닫혀 있고, 실제 작업은 람다로 확장 |
| **DRY** | 트랜잭션 boilerplate 를 한 번만 작성 |
| **Testability** | 비즈니스 로직만 별도로 unit test 가능 |
| **Spring 의 `JdbcTemplate`, `TransactionTemplate`** | 정확히 같은 패턴 |

## 6. 실전 패턴 ②: Strategy 를 람다로

```java
public class Discount {

    // Before: 인터페이스 + 구현체 클래스
    public interface DiscountPolicy {
        long apply(long price);
    }

    // After: 람다로 전략 주입
    public static final Function<Long, Long> SUMMER_SALE = price -> (long) (price * 0.8);
    public static final Function<Long, Long> VIP        = price -> price - 10_000L;

    public long checkout(long price, Function<Long, Long> policy) {
        return policy.apply(price);
    }
}
```

## 7. Method Reference (메서드 참조) 4가지

람다를 더 짧게 쓰는 문법.

| 종류 | 예시 | 같은 람다 |
| --- | --- | --- |
| **static** | `Integer::parseInt` | `s -> Integer.parseInt(s)` |
| **bound instance** | `System.out::println` | `s -> System.out.println(s)` |
| **unbound instance** | `String::toUpperCase` | `s -> s.toUpperCase()` |
| **constructor** | `ArrayList::new` | `() -> new ArrayList<>()` |

## 8. 람다 사용 시 주의점

### 8.1. effectively final 만 캡처 가능

```java
int count = 0;
Runnable r = () -> System.out.println(count);
count = 1; // ❌ 컴파일 에러: count 는 effectively final 이 아님
```

> Functional Programming 의 원칙: **함수는 외부 상태를 변경하지 않는다.**
> 자바는 이를 *컴파일 단계에서 강제* 합니다.

### 8.2. 람다 안에서 `this` 는 외부 인스턴스

```java
public class Outer {
    private String name = "Outer";

    public Runnable createTask() {
        return () -> System.out.println(this.name); // Outer.this
    }
}
```

### 8.3. 람다 안의 Checked Exception 문제

`Function`, `Predicate` 등 표준 인터페이스는 `throws` 가 없습니다. Checked Exception 을 던지는 람다는 컴파일 에러.

```java
// ❌ IOException 은 checked
Function<String, byte[]> reader = path -> Files.readAllBytes(Paths.get(path));
```

#### 해결: 자체 함수형 인터페이스 정의

```java
@FunctionalInterface
public interface ThrowingFunction<T, R, E extends Exception> {
    R apply(T t) throws E;
}
```

또는 람다 내부에서 `RuntimeException` 으로 wrapping.

## 9. 한 줄 정리

| 키워드 | 의미 |
| --- | --- |
| **함수형 인터페이스** | 추상 메서드가 정확히 1개인 인터페이스 (SAM) |
| **람다** | 함수형 인터페이스의 *간결한* 구현체 |
| **`@FunctionalInterface`** | 컴파일러가 SAM 규칙을 검사하게 함 |
| **표준 인터페이스** | `Function`, `Predicate`, `Consumer`, `Supplier` 부터 확인 |
| **메서드 참조** | `Class::method` 로 더 간결한 람다 |
| **활용** | Template Method (Callback), Strategy, Stream API |

> **핵심 한 줄**: "자바의 함수형 인터페이스는 *함수를 객체로 만들기 위한 어댑터* 다.
> 람다는 이 어댑터를 *글자 수 적게* 쓰는 방법일 뿐이다."
