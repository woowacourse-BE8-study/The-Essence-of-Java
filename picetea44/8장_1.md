## 리플렉션 API 가 뭐지 (겉핥기)

리플렉션은 JVM에 이미 메모리에 올라온 설계도 정보를 활용하는 것.

우리가 작성한 자바 코드를 실행하면, JVM의 클래스 로더는 코드들을 읽어 들여 메모리의 특정 영역에 클래스의 이름, 변수, 메서드, 접근 제어자 등 모든 구조 정보를 메타데이터 형태로 기록

리플렉션 API는 런타임에 이 `Class` 객체를 가져와서, JVM이 미리 정리해 둔 설계도를 합법적으로 열람할 수 있음

그래서 그 클래스에 어떤 변수와 기능이 있는지 파악할 수 있고 그 정보를 바탕으로 실행 중인 객체의 값을 강제로 바꾸거나 숨겨진 값을 바꿀 수 있음

인텔리제이도 쪼금 다르긴 하지만 리플렉션을 활용해서 편의 기능을 제공

- 마침표 찍었을 때 자동 완성
- 디버깅 모드에서 값 확인할 때
- Junit 테스트 개별 실행 (초록색 재생 버튼)

### 실제 예시 1: JUnit은 어떻게 `@Test` 메서드만 골라서 실행할까?

TDD를 적용하여 테스트 코드를 작성할 때 우리는 메서드 위에 `@Test` 애노테이션만 붙입니다. 테스트 프레임워크(JUnit)는 내부적으로 리플렉션을 사용해 이 애노테이션이 붙은 메서드만 찾아 실행합니다.

**우리가 작성하는 코드:**

```java
public class BlackjackTest {
    @Test
    public void hit_카드를_한장_더_받는다() {
        // 테스트 로직
    }

    public void helperMethod() {
        // 이 메서드는 @Test가 없으므로 실행되지 않음
    }
}
```

**JUnit이 내부적으로(리플렉션으로) 우리 코드를 실행하는 방식 (간략화된 원리):**

```java
import java.lang.reflect.Method;

public class JUnitRunner {
    public static void main(String[] args) throws Exception {
        // 1. 테스트할 클래스의 정보를 가져온다 (리플렉션)
        Class<?> testClass = Class.forName("BlackjackTest");
        Object testInstance = testClass.getDeclaredConstructor().newInstance();

        // 2. 클래스 안에 선언된 모든 메서드를 싹 가져온다 (리플렉션)
        Method[] methods = testClass.getDeclaredMethods();

        for (Method method : methods) {
            // 3. 메서드 위에 @Test 애노테이션이 붙어있는지 확인한다
            if (method.isAnnotationPresent(Test.class)) {
                // 4. 붙어있다면, 그 메서드를 강제로 실행(invoke)한다
                method.invoke(testInstance);
            }
        }
    }
}
```

우리가 `main` 메서드를 직접 호출하지 않았는데도 테스트가 실행되는 이유는, 프레임워크가 리플렉션을 통해 우리 코드를 스캔하고 조작하기 때문입니다.

### 실제 예시 2: 객체의 `private` 상태를 테스트해야 할 때

객체 지향 원칙에 따라 무분별한 `getter` 사용을 지양하고 캡슐화를 지키다 보면, 테스트 코드에서 객체의 내부 상태를 검증하기 난감한 상황이 생길 수 있습니다. (물론 상태보다는 행위를 테스트하는 것이 좋지만,
부득이한 경우 리플렉션을 씁니다.)

예를 들어, 블랙잭 게임에서 플레이어의 보유 금액(`money`)이 외부로 노출되지 않도록 `private`으로 닫아두었다고 가정해 보겠습니다.

**도메인 코드:**

```java
public class Player {
    private final String name;
    private int money; // getter가 없는 private 변수

    public Player(String name, int money) {
        this.name = name;
        this.money = money;
    }

    public void winBetting(int amount) {
        this.money += amount;
    }
}
```

**테스트 코드에서 리플렉션을 사용해 `money` 값을 검증하는 상황:**

```java
import org.junit.jupiter.api.Test;
import java.lang.reflect.Field;

import static org.assertj.core.api.Assertions.assertThat;

public class PlayerTest {
    @Test
    void 배팅에서_승리하면_돈이_증가한다() throws Exception {
        // given
        Player player = new Player("pobi", 10000);

        // when
        player.winBetting(5000);

        // then: getter가 없으므로 리플렉션으로 money 필드를 강제로 열어서 확인
        Field moneyField = Player.class.getDeclaredField("money");
        moneyField.setAccessible(true); // private 접근 허용

        int currentMoney = (int) moneyField.get(player); // 값 꺼내기

        assertThat(currentMoney).isEqualTo(15000);
    }
}
```
