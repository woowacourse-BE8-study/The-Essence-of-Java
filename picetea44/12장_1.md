## 애너테이션 만들기

애너테이션 만드는 방식은 두가지가 존재

- 컴파일 타임 처리 : 컴파일러 안에 로직이 존재 (롬복)
- 런타임 처리 : 리플렉션 기반 (스프링의 @RestController, @Transactional 등)

### 스프링 방식 (런타임)

특정 메서드의 실행 시간을 재고 싶을 때 사용할 @Timer 애너테이션을 만든다고 생각

```java
import java.lang.annotation.ElementType;
import java.lang.annotation.Retention;
import java.lang.annotation.RetentionPolicy;
import java.lang.annotation.Target;

@Target(ElementType.METHOD) // 메서드에만 붙일 수 있음
@Retention(RetentionPolicy.RUNTIME) // 프로그램 실행 중에도 정보를 유지함
public @interface Timer {
    // 아무런 데이터나 로직이 없는 빈 껍데기(마커), 필드는 가능 +
}
```

우리가 만든 타겟 클래스의 로직에 Timer 애너테이션을 적용

```java
// [실제 작성하는 코드] CalculationService.java

import org.springframework.stereotype.Service;

@Service // 스프링 컨테이너에 빈(Bean)으로 등록
public class CalculationService {

    @Timer // 우리가 만든 꼬리표 부착!
    public void heavyTask() {
        System.out.println("복잡한 계산을 시작합니다...");
        try {
            Thread.sleep(2000);
        } catch (InterruptedException e) {
        }
        System.out.println("복잡한 계산 완료.");
    }
}
```

이제 `@Timer` 꼬리표를 발견했을 때 가로채서 실행할 '시간 측정 엔진'을 만듬.

```java
// [실제 작성하는 코드] TimerAspect.java

import org.aspectj.lang.ProceedingJoinPoint;
import org.aspectj.lang.annotation.Around;
import org.aspectj.lang.annotation.Aspect;
import org.springframework.stereotype.Component;

@Aspect    // 이 클래스가 AOP 엔진임을 선언
@Component
public class TimerAspect {

    // 핵심!: @Timer 애너테이션이 붙은 메서드를 실행할 때 이 로직으로 가로채라!
    @Around("@annotation(Timer)")
    public Object measureTime(ProceedingJoinPoint joinPoint) throws Throwable {

        System.out.println("타이머 시작!");
        long startTime = System.currentTimeMillis();

        // 원본 메서드(heavyTask)를 진짜로 실행하는 부분
        Object result = joinPoint.proceed();

        long endTime = System.currentTimeMillis();
        System.out.println("=> 실행 시간: " + (endTime - startTime) + "ms\n");

        return result;
    }
}
```

프로그램을 실행하게되면(런타임)에 클래스를 분석하고 해당 애너테이션이 발견되면 원래의 로직이 적혀있던 코드를 삽입하여 서비스를 직접 호출하지 않고도 TimerEngine에게 넘겨서 해당 코드를 실행

```java
public class Main {
    public static void main(String[] args) throws Exception {
        CalculationService service = new CalculationService();

        // 서비스 객체를 직접 실행하지 않고 엔진에 맡깁니다.
        // TimerEngine.execute(service);
        calculationService.heavyTask();
    }
}
```

```java
가벼운 작업을
실행합니다 .

복잡한 계산을
시작합니다...
복잡한 계산
완료 .
=>[heavyTask]
실행 시간:2005ms
```

### 💡 총정리 흐름도

1. **개발자:** `@Timer` 만들고, `heavyTask`에 붙이고, `TimerAspect` 짠다. 끝.
2. **스프링 (서버 켜질 때):** 코드를 싹 스캔한다. "어? `heavyTask`에 `@Timer`가 있네? 그럼 원본 객체 말고 **프록시(가짜) 객체**를 만들어서 던져줘야겠다"
3. **스프링 (실행 중):** `AppRunner`에게 진짜 서비스 객체 대신 **프록시 객체**를 넘겨준다(의존성 주입).
4. **실행 (AppRunner):** 개발자는 원본인 줄 알고 `heavyTask()`를 호출했지만, 실제로는 프록시 객체의 메서드가 낚아채서 실행된다. 프록시는 `Aspect` 로직을 먼저 부르고, 그 안에서
   `proceed()`를 통해 진짜 `heavyTask()`를 실행한 뒤, 다시 시간을 잰다.
