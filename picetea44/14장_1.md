# 함수형 프로그래밍

## 1. 함수형 vs 명령형의 본질적 차이

> **명령형 (Imperative)**: "어떻게(How) 할 것인가?"
>
>
> 변수를 만들고, 값을 바꾸고, 반복문을 돌려서 결과를 만들어라.
>

개발자가 직접 반복문을 제어하고, 중간 상태를 저장할 변수를 만듭니다. 코드가 한 줄씩 실행될 때마다 변수의 상태가 끊임없이 변합니다.

```java
List<Integer> numbers = List.of(1, 2, 3, 4, 5);
List<Integer> result = new ArrayList<>(); // 상태를 저장할 빈 리스트 (계속 변함)

// i 또한 계속 변함
for(
int i = 0; i <numbers.

size();

i++){
int squared = numbers.get(i) * numbers.get(i);
    if(squared %2==0){
        result.

add(squared); // 외부 상태(result)를 직접 변경 (Mutation)
    }
            }
```

> **함수형 (Functional)**: "무엇을(What) 할 것인가?"
>
>
> 원본 데이터는 건드리지 말고, 함수라는 상자에 넣어 변형된 새로운 데이터를 뽑아내라.
>

값이 변하는 변수(`i`, `result`) 자체가 등장하지 않습니다. 기존 값을 재활용(수정)하지 않고 새로운 객체를 생성하므로, **멀티 스레드 환경에서 동시성 문제(Race Condition)를 완벽하게 회피
**할 수 있습니다.

```java
List<Integer> numbers = List.of(1, 2, 3, 4, 5);

List<Integer> result = numbers.stream()
        .map(n -> n * n)         // 데이터 변형 1: 제곱해라
        .filter(n -> n % 2 == 0) // 데이터 변형 2: 짝수만 남겨라
        .toList();               // 최종 결과 조립
```

---

## 2. 함수형 프로그래밍은 '추상화'의 결과물이다

`map`이나 `filter` 같은 함수형 메서드를 호출하더라도, 그 **내부적으로는 어차피 명령형 프로그래밍(for문, if문)이 작성**되어 있습니다.

- **기계적 동작의 위임:** 우리는 기계가 어떻게 반복을 도는지 내부 동작을 알 필요 없이, 메서드의 기능(논리)만 알고 조립해서 사용하면 됩니다.
- **이점:** 이러한 고도의 추상화 덕분에 개발자는 저수준의 제어(인덱스 관리, 변수 업데이트)에서 벗어나 **더 논리적이고, 안전하며, 편리하게** 코드를 작성할 수 있습니다.

## 3. 함수형을 완성하는 필수 3요소

### ① 불변성 (Immutability)

**상태를 수정하지 않고, 변경된 상태를 가진 '새로운 복사본'을 반환한다.**

**❌ 불변성 미적용 (상태 변경의 공포)**

메서드 실행 중 에러가 발생하면 롤백이 되지 않아 원본 데이터가 영구적으로 훼손될 위험이 있습니다.

```java
`public boolean isDangerousMove(Piece piece, int targetX, int targetY) {
    int originalX = piece.getX(); // 1. 움직이기 전 위치 백업
    int originalY = piece.getY();

    piece.setX(targetX); // 2. 원본 기물을 움직여 봄 (상태 변경!)
    piece.setY(targetY);

    boolean dangerous = board.isUnderAttack(piece); // 3. 위험한지 확인

    // 💥 만약 여기서 예기치 않은 에러가 터지면 원본이 훼손된 채로 남음!
    piece.setX(originalX); // 4. 다행히 에러가 안 났다면 원래 위치로 롤백
    piece.setY(originalY);

    return dangerous;
}`
```

**✅ 불변성 적용 (롤백 불필요)**

복사본으로 마음껏 시뮬레이션을 돌리므로, 원본 훼손의 위험이 0%가 됩니다.

```java
public boolean isDangerousMove(Piece piece, int targetX, int targetY) {
    // 1. 원본은 놔두고, 이동된 위치를 가진 '새로운 복사본 말'을 생성함
    Piece simulatedPiece = piece.move(targetX, targetY);

    // 2. 이 복사본으로 마음껏 시뮬레이션을 돌림
    return board.isUnderAttack(simulatedPiece);
    // 끝! 백업도, 롤백 코드도 필요 없음.
}
```

### ② 순수 함수 (Pure Function)

**동일한 입력에는 항상 동일한 출력을 반환하며, 외부 상태를 읽거나 건드리지 않는다.**

- 부작용(Side Effect)이 없기 때문에 어떤 상황에서든 결과를 100% 예측할 수 있습니다.
- 복잡한 환경 셋팅(Mocking) 없이 독립적인 **단위 테스트(TDD)**를 작성하기가 매우 쉬워집니다.

```java
// 비순수
public class ScoreManager {
    private int bonus = 10; // 외부 상태

    // 문제점 1. 외부 상태에 의존함 (bonus 값에 따라 결과가 달라짐)
    // 문제점 2. 외부 상태를 몰래 변경함 (부작용 발생)
    public int calculateTotal(int score) {
        this.bonus += 5;
        return score + this.bonus;
    }
}

// 순수 
public class ScoreManager {
    // 1. 외부 변수를 읽지도, 변경하지도 않음
    // 2. 입력값이 같으면 항상 같은 출력값을 보장함 (예측 가능)
    public int calculateTotal(int score, int bonus) {
        return score + bonus;
    }
}
```

### ③ 일급 객체 (First-Class Object)

**함수(로직)를 변수처럼 취급하여, 다른 함수에 파라미터로 던져주거나 반환값으로 꺼내 쓸 수 있다.**

- **변수나 데이터 구조에 담을 수 있다.** (함수를 변수에 저장 가능)
- **함수의 파라미터(인자)로 전달할 수 있다.** (함수를 재료로 던짐)
- **함수의 결과로 반환할 수 있다.** (함수가 함수를 만들어 냄)

```java
// 1. 함수를 변수에 저장 (조건 1)
Function<Integer, Integer> addTen = x -> x + 10;

// 2. 함수를 다른 메서드(.map)의 인자로 전달 (조건 2)
// 여기서 .map은 '고차 함수'가 됨
List<Integer> result = List.of(1, 2, 3).stream()
        .map(addTen)
        .toList();

// 3. 함수를 반환하는 함수 (조건 3)
public Function<Integer, Integer> getOperator(String type) {
    return x -> x * x; // 함수 자체를 결과로 던짐
}
```
