# [Java] Set 컬렉션 정리: HashSet vs TreeSet

자바의 `Set` 인터페이스는 **중복을 허용하지 않는 데이터의 집합**을 다룬다. 대표적인 구현체인 `HashSet`과 `TreeSet`의 내부 동작 원리와 중복 판별 기준을 정리했다.

---

## 1. 배경 지식

컬렉션을 이해하기 위해서는 뼈대가 되는 자료구조를 먼저 알아야 한다.

- **해시 테이블 (Hash Table)**
    - 데이터를 '키(Key)'와 '값(Value)'의 쌍으로 저장하는 구조다.
    - '해시 함수'를 통해 키를 고유한 인덱스로 변환하므로 데이터 접근 속도가 매우 빠르다 (O(1)).
    - 자바에서는 이를 **`HashMap`** 클래스로 구현했다.
- **이진 탐색 트리 (Binary Search Tree)**
    - "부모 노드보다 작은 값은 왼쪽, 큰 값은 오른쪽"에 배치하는 엄격한 규칙을 가진 트리 구조다.
    - 데이터 삽입과 동시에 자동으로 정렬되며, 탐색 속도는 빠르다 ($O(\log n)$).
    - 자바에서는 이를 업그레이드한 레드-블랙 트리 기반의 **`TreeMap`** 클래스로 구현했다.

---

## 2. HashSet (해시셋)

`HashSet`은 빠른 검색과 중복 제거가 목적일 때 사용하는 가장 기본적인 Set이다.

- **내부 동작 원리**
    - `HashSet`은 빈 껍데기이며, 내부적으로 **`HashMap`*을 가져다 쓴다.
    - 저장하려는 데이터를 맵의 '키(Key)'로 밀어 넣고, 값(Value)에는 의미 없는 더미(Dummy) 객체를 채워 넣는 방식으로 맵의 '키 중복 불가' 특성을 활용한다.
- **특징**
    - 데이터의 저장 순서를 보장하지 않는다.
    - 시간 복잡도가 평균 **$O(1)$**로 매우 빠르다.

### 🔍 HashSet의 중복 판별 로직 (2단계 검증)

사용자 정의 객체를 넣을 때 **반드시 `hashCode()`와 `equals()`를 오버라이딩**해야 하는 이유가 여기에 있다.

1. **1차 관문 (`hashCode` 비교):** 들어온 객체의 해시코드 값을 확인한다.
    - 기존 객체들과 겹치는 해시코드가 없다면? 👉 **새로운 객체로 판정 (저장 완료)**
    - 겹치는 해시코드가 있다면? 👉 **2차 관문으로 이동**
2. **2차 관문 (`equals` 비교):** 해시코드가 같은 객체끼리 실제 내부 내용이 같은지 비교한다.
    - 결과가 `true`면 👉 **중복 데이터로 판정 (저장 거절)**
    - 결과가 `false`면 👉 우연히 해시코드만 겹친 다른 데이터(해시 충돌)로 판정 **(저장 완료)**

> **[💡 핵심 요약]** > 1차로 `hashCode()`를 통해 그룹을 빠르게 찾고, 2차로 `equals()`를 통해 진짜 중복인지 정밀 검사한다.
>

## 3. TreeSet (트리셋)

`TreeSet`은 중복 제거와 더불어 **데이터의 자동 정렬**이 필요할 때 사용한다.

- **내부 동작 원리**
    - `TreeSet` 역시 내부적으로 `TreeMap`을 사용한다.
    - 데이터를 맵의 '키(Key)'로 넣으면, 이진 탐색 트리의 규칙에 따라 작으면 왼쪽, 크면 오른쪽으로 자리를 찾아가며 저장된다.
- **특징**
    - 데이터 삽입 시 자동으로 오름차순(또는 사전순) 정렬된다.
    - 트리를 타고 내려가며 위치를 찾아야 하므로 시간 복잡도는 O(log n)이다.

### 🔍 TreeSet의 중복 판별 로직 (크기 비교)

`TreeSet`은 `hashCode()`나 `equals()`를 **전혀 사용하지 않는다.**

1. **객체 간의 대소 비교:** 데이터를 삽입할 때 `compareTo()` 또는 `compare()` 메서드를 호출하여 기존 노드들과 크기를 비교한다.
2. **중복 판정:** 비교 결과가 `0`이 나오면 (즉, 크기가 완전히 같다고 판별되면) **중복 데이터로 판정하여 저장하지 않는다.**

> **[💡 핵심 요약]**
>
>
> 직접 만든 객체를 `TreeSet`에 넣으려면 반드시 클래스에 `Comparable` 인터페이스를 구현(implements)하거나, 셋을 생성할 때 `Comparator`를 넘겨주어 **정렬 기준(크기 비교
기준)을 명시**해야 한다.
>

## 4. 한눈에 보는 요약 비교표

| **구분**        | **HashSet**                              | **TreeSet**                            |
|---------------|------------------------------------------|----------------------------------------|
| **기반 클래스**    | `HashMap` (해시 테이블)                       | `TreeMap` (레드-블랙 트리)                   |
| **정렬 여부**     | ❌ 순서 보장 안 됨                              | ✅ 자동 정렬 됨                              |
| **시간 복잡도**    | **O(1)** (가장 빠름)                         | **O(\log n)** (탐색 비용 발생)               |
| **중복 판별 기준**  | `hashCode()` 일치 ➡️ `equals()`가 `true`일 때 | `compareTo()` / `compare()` 결과가 `0`일 때 |
| **필수 구현 메서드** | `hashCode()`, `equals()` 오버라이딩           | `Comparable` 또는 `Comparator` 구현        |
| **사용 시기**     | 순서 상관없이 중복만 빠르게 제거할 때                    | 중복 제거 + **데이터 정렬**이 항상 필요할 때           |
