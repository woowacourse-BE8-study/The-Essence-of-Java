## 1. 관점별 용어 매핑 테이블

| **바라보는 관점**             | **무엇을 가지고 있는가? (Data)**                                                            | **무엇을 하는가? (Logic)**      | **설명**                                                                                                |
|-------------------------|------------------------------------------------------------------------------------|---------------------------|-------------------------------------------------------------------------------------------------------|
| **기획 / 개념 설계**          | **속성** (Property)                                                                  | **기능** (Function)         | 코드를 짜기 전, "이 객체는 어떤 특징이 있고 뭘 할 수 있어야 해?"라고 우리말로 아이디어를 낼 때.                                            |
| **객체지향 설계 (OOP)**       | **상태** (State)                                                                     | **행위** (Behavior),        
 **책임** (Responsibility) | "이 객체가 어떤 정보를 책임지고, 어떤 행동을 해야 하는가?"를 논의할 때. (※ 다른 객체와 상호작용하기 위해 '메시지'를 주고받는다고 표현함) |
| **코드 구현 (Java)**        | **필드** (Field)                                                                     | **메서드** (Method)          | IDE를 켜고 실제 자바 문법으로 클래스 내부에 코드를 작성할 때. (※ 클래스 영역에 선언된 변수를 '멤버 변수'라고도 하지만, 자바 공식 문서에서는 'Field'를 표준으로 씀) |
| **프로그램 실행 시**           | **상태 값** (State Value)                                                             | **실행, 호출** (Call, Invoke) | 프로그램이 돌아가는 런타임(Runtime) 중, 메모리에 올라간 특정 인스턴스가 현재 쥐고 있는 구체적인 데이터 값.                                     |
| **데이터베이스 (DB)**         | **컬럼** (Column)                                                                    | **프로시저** (Procedure)      | 영속성을 위해 데이터를 테이블 형태로 DB에 저장하고 다룰 때.                                                                   |

## 2. '데이터(Data)'를 부르는 용어들의 미세한 차이

- **필드 (Field):** 자바 클래스 내부에 선언된 **'변수 공간' 그 자체**를 지칭하는 물리적인 단어
    - *예:* "이 클래스에는 `score`라는 필드가 있습니다."
- **상태 (State):** 특정 시점에 객체의 필드가 가지고 있는 **'논리적인 값'**을 의미합니다. 상태는 반드시 변하는 것만 의미하지 않음.
    - **가변 상태 (Mutable):** 진행 상황에 따라 계속 변하는 값. (예: 게임 진행 중 플레이어의 현재 점수, 보유 금액)
    - **불변 상태 (Immutable):** 객체가 태어날 때 확정되어 죽을 때까지 절대 변하지 않는 값. 객체의 안정성을 위해 자바에서는 `final` 키워드를 적극 권장합니다. (예: 카드 객체의 무늬(
      Spade)와 숫자(Ace))

## 3. '로직(Logic)'을 부르는 용어들의 미세한 차이

- **메서드 (Method):** 클래스 안에 구현된 **'함수 코드 덩어리'** 자체를 가리키는 기술적 용어
- **행위 (Behavior):** 객체가 자신의 상태를 변경하거나, 외부의 요청에 응답하는 '의미 있는 동작'. (단순히 필드 값을 꺼내주는 Getter/Setter는 진정한 의미의 행위라고 보기 어려움.)
- **메시지 (Message):** 객체지향의 꽃. 한 객체가 다른 객체의 메서드를 호출하는 것을 "메시지를 보낸다"라고 표현.
    - *관점의 차이:*
        - "A가 B의 `calculate()` **메서드를 실행했다**" (코드 관점)
        - "A가 B에게 계산해 달라고 **메시지를 보냈다**" (OOP 설계 관점)

```java
// [기획 관점] "카드(Card)는 무늬와 숫자를 '속성'으로 가진다."
public class Card {

    // [코드 관점] 클래스 내부에 선언된 '필드(Field)'
    // [OOP 관점] 한 번 생성되면 절대 변하지 않는 '불변 상태(Immutable State)'
    private final String suit;
    private final String denomination;

    public Card(String suit, String denomination) {
        this.suit = suit;
        this.denomination = denomination;
    }
}

public class Player {

    // [OOP 관점] 카드를 받을 때마다 리스트에 추가되므로 '가변 상태(Mutable State)'
    private final List<Card> hand = new ArrayList<>();

    // [코드 관점] '메서드(Method)'
    // [OOP/설계 관점] 플레이어가 카드를 받는 '행위(Behavior)'
    public void drawCard(Card card) {
        this.hand.add(card); // 자신의 상태를 스스로 변경함
    }
}

public class GameLogic {
    public void play() {
        Player player = new Player();
        Card card = new Card("Spade", "A");

        // [OOP 관점] GameLogic이 Player에게 "카드 받아라!" 라고 '메시지(Message)'를 보냄
        player.drawCard(card);
    }
}
```
