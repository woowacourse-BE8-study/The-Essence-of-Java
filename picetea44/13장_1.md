## 프로그램 vs 프로세스

| **구분**    | **프로그램 (Program)**                      | **프로세스 (Process)**          |
|-----------|-----------------------------------------|-----------------------------|
| **정의**    | 디스크에 저장된 정적인 실행 파일 (`.class`, `.jar` 등) | 메모리에 적재되어 CPU가 실행 중인 동적인 상태 |
| **자원 사용** | CPU, 메모리 사용 안 함                         | 운영체제로부터 독립적인 메모리 공간 할당받음    |

---

## 프로세스 메모리 구조

운영체제가 프로세스에 할당하는 독립적인 메모리 공간은 4가지 영역으로 나뉩니다.

- **Code (코드)**: 실행할 프로그램의 소스 코드 (기계어)
- **Data (데이터)**: 전역 변수, 정적(`static`) 변수
- **Heap (힙)**: 런타임에 동적으로 할당되는 데이터 (예: `new` 키워드로 생성된 인스턴스)
- **Stack (스택)**: 메서드 호출 시 임시로 생성되는 지역 변수, 매개 변수, 리턴 주소

---

## 스레드(Thread)의 자원 사용 방식

스레드는 프로세스 내에서 코드를 실제로 실행하는 **최소 실행 흐름 단위**입니다. 스레드는 프로세스의 자원을 공유 영역과 독립 영역으로 나누어 사용합니다.

### 1. 스레드 간 '공유'하는 자원

- **영역**: Code, Data, Heap
- **특징**: 프로세스 내의 모든 스레드가 함께 사용합니다. 여러 스레드가 동시에 Heap 영역의 동일한 객체 상태를 변경할 수 있으므로 동시성(Concurrency) 문제가 발생할 수 있으며, 동기화(
  Synchronization) 처리가 필요합니다.

### 2. 스레드 별 '독립' 자원

- **Stack (스택)**: 스레드마다 고유의 스택을 할당받아 다른 스레드의 지역 변수에 접근할 수 없습니다. 이를 통해 독립적인 메서드 실행 흐름을 보장합니다.
- **PC 레지스터**: 여러 스레드가 CPU를 번갈아 사용할 때, 현재 해당 스레드가 Code 영역의 어느 위치를 실행 중인지 주소를 기억합니다.
