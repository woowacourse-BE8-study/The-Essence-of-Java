## **1. 지네릭 클래스의 객체 생성과 사용**

---

### **1) 지네릭 클래스의 정의와 인스턴스 변수**

- 지네릭 클래스 `Box<T>`가 정의되어 있을 때, 해당 클래스의 객체에는 한 가지 종류(T 타입)의 객체만 저장할 수 있다.
- 내부적으로 `ArrayList<T>`를 사용하여 여러 객체를 저장할 수 있도록 구현하며, `add`, `get`, `size` 등의 메서드 또한 지네릭 타입 `T`를 사용하여 타입 안전성을 확보한다.

### **2) 객체 생성 시 타입 일치 원칙**

- 지네릭 클래스의 객체를 생성할 때, **참조변수에 지정된 타입과 생성자에 대입된 타입은 반드시 일치**해야 한다. 일치하지 않으면 컴파일 에러가 발생한다.
- **예시:**
    - `Box<Apple> appleBox = new Box<Apple>();` // **OK**
    - `Box<Apple> appleBox = new Box<Grape>();` // **에러** (타입 불일치)
- **상속 관계에서의 주의:** `Apple`이 `Fruit`의 자손이더라도 `Box<Fruit> appleBox = new Box<Apple>();`과 같이 대입된 타입이 다르면 대입할 수 없다.

### **3) 지네릭 클래스 간의 다형성**

- 대입된 타입이 동일하고, **지네릭 클래스 자체가 상속 관계**에 있는 경우에는 다형성을 적용할 수 있다.
- **예시:** `FruitBox<T>`가 `Box<T>`의 자손 클래스라면 아래 문장은 허용된다.
    - `Box<Apple> appleBox = new FruitBox<Apple>();` // **OK**

### **4) 타입 추론과 다이아몬드 연산자**

- **JDK 1.7**부터는 타입 추론(Type Inference) 기능이 강화되어, 생성자 쪽의 타입을 생략할 수 있게 되었다.
- 참조변수의 타입을 통해 생성자에 대입될 타입을 명확히 알 수 있으므로, 빈 괄호 `<>`만 남겨두면 된다. 이를 **다이아몬드 연산자**라고 한다.
    - `Box<Apple> appleBox = new Box<>();` // **OK** (생략 가능)

### **5) 객체 추가와 타입 제한**

- `void add(T item)` 메서드를 통해 객체를 추가할 때, 대입된 타입과 다른 타입의 객체는 추가할 수 없다.
- `Box<Apple>`에는 오직 `Apple` 객체만 추가 가능하며, 상속 관계가 없는 `Grape` 등은 추가 시 에러가 발생한다.

## **2. Q & A**

---

### **Q1. `new ArrayList<>()`에서 `<>`는 타입을 생략하는 것인가?**

**A:** 그렇다. 이를 **다이아몬드 연산자**라고 부른다. 컴파일러가 대입 연산자 왼쪽의 참조변수 타입을 보고 오른쪽 생성자의 타입을 자동으로 추론해주기 때문에 생략이 가능한 것이다. 덕분에 코드가 더
간결해진다.

### **Q2. `<>`는 무조건 지네릭을 의미한다고 보면 되는가?**

**A:** 그렇다. 자바 문법에서 클래스나 메서드 이름 뒤에 붙는 `< >`는 지네릭스(Generics)를 나타내는 고유한 기호다.

- 선언부에서는 **타입 매개변수**임을 나타낸다.
- 인스턴스 생성 시에는 **구체적인 타입**을 지정하는 역할을 수행한다.
