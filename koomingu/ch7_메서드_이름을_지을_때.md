### `getLocation()`에 대한 고찰 - 왜 `getLocationString()`이 아닐까?

- `getLocation()`은 "현재 객체의 위치 정보를 가져온다"는 **행위의 목적**에 집중한 이름임

### 객체 지향 언어에서 이름에 타입을 명시하지 않는 이유

- **추상화:** 사용자는 위치 정보를 원할 뿐, 그것이 내부적으로 `String`인지 `Point` 객체인지 일일이 이름에서 확인하지 않아도 되도록 설계함
- **다형성과 오버라이딩:** 조상 클래스에서 `getLocation()`이라고 정의했다면, 자손에서도 반드시 동일한 이름을 써야 오버라이딩이 성립함
- **유지보수:** 나중에 반환 타입을 `String`에서 다른 커스텀 객체로 바꾼다면, 이름에 `String`이 들어있는 경우 모든 호출부의 메서드 이름을 수정해야 함

### 반환 타입을 고려한 메서드 명명 가이드

1. 일반적인 정보 취득: `get + 변수명` → 반환 타입보다는 **가져오려는 데이터의 의미**에 집중함
    - `getName()` (반환: String)
    - `getAge()` (반환: int)
    - `getCreatedAt()` (반환: LocalDateTime)
2. 논리값 반환 (Boolean): `is / has / can` → 이름만으로도 "참/거짓"임을 알 수 있도록 접두사를 붙임
    - `isEmpty()`: 비어있는가?
    - `hasRole()`: 권한을 가지고 있는가?
    - `canExecute()`: 실행 가능한가?
3. 타입 변환: `to + 타입명` → 객체를 다른 형태나 타입으로 명시적으로 변환할 때 사용
    - `toString()`: 객체를 문자열로 변환
    - `toList()`: 배열이나 스트림을 List로 변환
    - `toDto()`: Entity를 DTO 객체로 변환
4. 명시적 표현이 필요한 경우: `as + 타입명` → 현재 객체를 특정 인터페이스나 타입으로 간주하여 취급할 때 사용
    - `asMap()`: 현재 데이터를 Map 형태로 간주하여 반환

### 요약

- **메서드 이름은 '어떻게(How/Type)'보다 '무엇을(What/Role)' 하는지 보여줘야 함**
- **기본 원칙:** 반환 타입은 이름보다는 문서(JavaDoc)나 **반환형 선언부**를 통해 확인하게 하고, 이름은 메서드의 의도를 담기
- **예외 상황:** 만약 한 클래스 내에서 동일한 데이터를 여러 타입으로 반환해야 한다면(예: `getLocationAsStr()`, `getLocationAsObj()`), 그때는 이름을 통해 타입을 구분해
  주는 것이 좋은 관례임
