## 1. 공변성 vs 반공변성

- **공변성**: 자식 타입을 허용한다. 즉, 더 구체적인 타입을 사용할 수 있다.
- **반공변성**: 부모 타입을 허용한다. 즉, 더 일반적인 타입을 사용할 수 있다.
- **불공변성**: 타입 사이에 상속 관계가 있어도 서로 다른 타입으로 취급한다.

## 2. 배열은 공변이다

자바 배열은 공변성을 가진다.

```java
Integer[] ints = new Integer[10];
Object[] objs = ints; // 가능하다.
```

즉, Integer가 Object의 하위 타입이면 Integer[]도 Object[]의 하위 타입으로 취급된다.
Integer <: Object 이면 Integer[] <: Object[] 가 성립한다.

하지만 다음과 같은 코드도 컴파일은 가능하다.
```java
objs[0] = "문자열";
```
이 코드는 컴파일 단계에서는 문제가 없지만, 실제 배열의 타입은 Integer[]이기 때문에 문자열을 저장할 수 없다.

따라서 실행 시점에 `ArrayStoreException` 예외가 발생한다.

즉, 배열은 공변이기 때문에 사용하기 편한 부분도 있지만, 컴파일 단계에서 모든 타입 오류를 막지 못한다.
그래서 런타임에 타입 안정성이 깨질 수 있다.

## 3. 제네릭은 불공변이다

자바 제네릭 타입은 기본적으로 불공변이다.
```java
List<Integer> ints = new ArrayList<>();

List<Object> objs = ints; // 컴파일 에러
```
Integer는 Object의 하위 타입이지만, List<Integer>는 List<Object>의 하위 타입이 아니다.

즉, 다음 관계는 성립하지 않는다.
```
Integer <: Object 이지만 List<Integer> <: List<Object> 는 성립하지 않는다.
```
제네릭은 배열과 달리 컴파일 단계에서 위험한 타입 대입을 차단한다.
이를 통해 런타임 오류를 줄이고 타입 안정성을 높인다.


## 4. 와일드카드로 제한적인 공변성과 반공변성을 표현한다

자바 제네릭은 기본적으로 불공변이지만, 와일드카드를 사용하면 제한적으로 공변성과 반공변성을 표현할 수 있다.

### 4-1. ? extends는 공변성을 표현한다
`List<? extends Number>`

위 타입에는 다음과 같은 리스트를 대입할 수 있다.

```
List<Integer>
List<Double>
List<Number>
```
즉, Number 또는 Number의 하위 타입을 허용한다.

따라서 ? extends Number는 값을 꺼내서 읽는 상황에 적합하다.

### 4-2. ? super는 반공변성을 표현한다
`List<? super Integer>`

위 타입에는 다음과 같은 리스트를 대입할 수 있다.

```
List<Integer>
List<Number>
List<Object>
```

즉, Integer 또는 Integer의 상위 타입을 허용한다.

따라서 ? super Integer는 값을 넣는 상황에 적합하다.

## 5. 자바 타입 시스템 기준 정리

자바 배열은 공변이기 때문에 런타임 타입 오류가 발생할 수 있다.
반면 제네릭은 기본적으로 불공변이기 때문에 컴파일 단계에서 타입 안정성을 보장한다.
그리고 와일드카드를 사용하면 필요한 경우에 한해 공변성과 반공변성을 표현할 수 있다.
