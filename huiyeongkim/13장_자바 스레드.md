## 1. 스레드 생성 방법
(1) `Thread` 클래스 상속

(2)  `Runnable` 인터페이스 구현

→ **왜 Runnable이 권장되나?** 

Java는 단일 상속만 가능하므로 Thread를 상속하면 다른 클래스를 상속할 수 없게 된다.
그러나, Runnable은 인터페이스라 제약이 없다.

## 2. 자바의 스레드

```java
main 쓰레드          ← 우리가 작성하는 코드가 실행되는 곳
GC 쓰레드            ← 가비지 컬렉션
JIT 컴파일러 쓰레드    ← 바이트코드 → 네이티브 코드 최적화
Finalizer 쓰레드     ← finalize() 처리
기타 내부 쓰레드들
```

- `main()` 메서드도 사실 **main 쓰레드** 위에서 실행된다.

## 3. main 쓰레드의 특징

- `main()` 메서드를 실행하는 쓰레드가 딱 하나 존재한다.
- 코드는 **위에서 아래로 순차 실행**한다.
- main 쓰레드가 종료되면 프로그램 종료한다.

```plaintext
- 블로킹 : 작업이 끝날 때까지 해당 쓰레드가 멈춰서 대기한다.
- 논블로킹 : 작업을 맡겨두고 쓰레드가 다른 일을 계속 진행한다.

→ Java 기본 = 블로킹
```

## 4. 진짜 실무에서 깨지는 순간

(1) 라이브러리 / API가 스레드를 만든다

```java
CompletableFuture.runAsync(() -> {
		count++;
});
```

Thread 안 만들었지만 내부적으로는 **다른 스레드에서 실행**한다.

(2) 콜백 / 비동기 / 이벤트

- Timer
- ExecutorService
- Netty / Spring
- DB 커넥션 풀

→ 전부 내부적으로 멀티 스레드이다.

(3) 백엔드 

Spring는 멀티 스레드 환경이다.

```
요청 1개 = 스레드 1개
```

## 5. 결론

순수 자바 + Thread도 안 만듦 + 비동기도 없음
-> 사실상 싱글 스레드이다.
