# 스트림 vs for 문 정리

`for`문은 반복 과정을 개발자가 직접 제어하는 방식이다.  
반면 `stream`은 데이터를 처리하는 과정을 파이프라인으로 선언하는 방식이다.

따라서 `for`문은 단순하고 직접적인 반복에 적합하고,  
`stream`은 필터링, 변환, 수집처럼 데이터 처리 흐름을 표현할 때 적합하다.


## 1. for 문

```java
int sum = 0;
for (int n : numbers) {
    if (n % 2 == 0) {
        sum += n;
    }
}
```

// 흐름
1. 숫자 하나를 꺼낸다.
2. 짝수인지 검사한다.
3. 짝수이면 더한다.

for문은 반복 흐름이 직접 드러난다.
따라서 단순 반복이나 성능이 민감한 코드에서 사용하기 좋다.

<br>

## 2. stream
```java
int sum = numbers.stream()
    .filter(n -> n % 2 == 0)
    .mapToInt(n -> n)
    .sum();
```

// 내부 흐름
1. stream()으로 스트림을 만든다.
2. filter()로 짝수만 통과시키는 단계를 등록한다.
3. mapToInt()로 Integer를 int 흐름으로 바꾼다.
4. sum()이라는 최종 연산이 호출될 때 실제 처리가 시작된다.

stream의 중간 연산은 바로 실행되지 않는다.
filter, mapToInt 같은 중간 연산은 파이프라인에 등록만 된다.
그리고 sum() 같은 최종 연산이 호출될 때 실제 데이터 처리가 일어난다.

즉, 다음처럼 동작한다고 볼 수 있다.

```
1. 꺼냄 → filter → 통과 못 하면 버림
2. 꺼냄 → filter → 통과하면 mapToInt → sum에 반영
3. 꺼냄 → filter → 통과 못 하면 버림
4. 꺼냄 → filter → 통과하면 mapToInt → sum에 반영
```

중요한 점은 stream이 단계마다 전체 데이터를 반복하는 구조가 아니라는 점이다.
보통은 최종 연산이 실행될 때 요소 하나씩 파이프라인을 통과한다.

<br>

## 3. stream의 오버헤드

stream은 for문보다 내부 구조가 복잡하다.

for문은 반복문 안에서 조건 검사와 합산을 직접 수행한다.
반면 stream은 람다와 파이프라인 구조를 통해 데이터를 처리한다.

```
람다 호출 비용
파이프라인 구성 비용
중간 연산과 최종 연산을 연결하는 내부 처리 비용
객체와 추상화로 인한 비용
```
그래서 위와 같은 추가 비용이 발생한다.
이런 비용을 stream의 오버헤드라고 볼 수 있다.

하지만 이 오버헤드가 항상 큰 것은 아니다.
데이터가 적거나 일반적인 비즈니스 코드에서는 거의 체감되지 않는 경우가 많다.
DB 조회, 네트워크 호출, 파일 입출력 같은 작업에 비하면 매우 작은 차이일 수 있다.

다만 반복 횟수가 매우 많거나 성능이 중요한 구간에서는 for문이 더 유리할 수 있다.

<br>

## 4. for문이 더 어울리는 경우
- 단순 반복일 때
- 성능이 민감한 코드일 때
- 인덱스가 필요할 때
- break, continue로 흐름을 세밀하게 제어해야 할 때
- 반복 중 여러 상태값을 함께 변경해야 할 때

<br>

## 5. stream이 더 어울리는 경우
- 필터링, 변환, 정렬, 수집 흐름이 있을 때
- 데이터 처리 과정을 선언적으로 표현하고 싶을 때
- map, filter, collect 흐름이 명확할 때
- 원본 데이터를 바꾸기보다 새로운 결과를 만들고 싶을 때

<br>

## 6. 최종 정리

for문은 반복을 직접 제어하는 방식이다.
stream은 데이터 처리 흐름을 파이프라인으로 표현하는 방식이다.

단순 반복과 성능이 중요한 구간에서는 for문이 적합하다.
데이터를 필터링하거나 변환하는 흐름을 명확하게 표현하고 싶을 때는 stream이 적합하다.

stream의 오버헤드란 데이터를 바로 반복하는 대신 람다와 파이프라인 구조를 거쳐 처리하는 데서 생기는 추상화 비용이라고 볼 수 있다.


- for문 = 직접 반복 제어
- stream = 데이터 처리 흐름 선언

- for문 = 단순하고 직접적
- stream = 표현력이 좋지만 약간의 오버헤드가 있을 수 있음
